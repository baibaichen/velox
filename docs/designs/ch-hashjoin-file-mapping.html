ClickHouse 坐标式 Hash Join → Velox (exec/ch) 移植文件对照

commit 235a13b45 · 分支 ch-hashjoin · Port 行数为 .h + .cpp 合计，wc -l 实测 · CH 源在 ClickHouse/src/
结论：核心算法文件全部「算法对齐 / 概念对齐」，无逐行源码搬运；4 个 velox 算子适配层无 CH 对应。
Port 把 CH 专有依赖（ProfileEvents、Block/Chunk、Arena=Common/Allocator、logger 等）剥离， 算法骨架用 velox 原语（VELOX_CHECK / MemoryPool / DecodedVector / RowVector / simd）重写。 坐标式 = 命中不拷贝 build 行，只存 64-bit RowRef 坐标（driver/batch/row），输出阶段再解引用物化， 对应 CH 的 RowRef/RowRefList + LazyOutput。Port 侧另有一层 velox 算子适配（Operator/JoinBridge/PlanNode）， 这层是 velox 执行框架要求、CH 无对应。

※ 算法对齐 = 照 CH 算法逻辑重写，剥掉 CH 专有依赖、换 velox 原语。
※ 概念对齐 = 对应 CH 某抽象但接口形态不同：HashTableAllocatorAdapter 把 CH HashTableAllocator 的 alloc/realloc/free 接口改走 velox MemoryPool；RetainedVectorsIndex 对应 CH 保活 build Block 的 StoredColumnsIndex，velox 侧改为保活 RowVector。
※ velox 新增 = velox 执行框架适配层（Operator / JoinBridge / core::PlanNode），CH 无对应。
※ CH 行数带 * = 该 CH 文件不止服务这一个 Port 文件（如 HashMethod.h 同时是 FixedKey/HashedKey 的源， HashJoinMethodsImpl.h 同时是 build/probe 的源），行数非一对一，仅作规模参考；带 + = 对应多个 CH 文件的合计起点。
数据准确性说明
  • Port 行数为 wc -l 实测的 .h + .cpp 合计（commit 235a13b45）。
  • CH 行数为对应 CH 源文件实测；多对多处（HashMethod / HashJoinMethods / AddedColumns）不做百分比对比，因一个 CH 文件服务多个 Port 文件、无法一对一归属。
  • 对齐类型由实际读两边代码判定（非文件名猜测）：EmitGather 确认对应 CH LazyOutput + HashJoinResult 的输出物化；RetainedVectorsIndex 是 CH StoredColumnsIndex 的概念对齐而非纯 velox 新增。
Port 侧新增（无 CH 对应：算子框架 / 测试 / benchmark）
  • 4 个算子适配层：ChHashBuildOperator / ChHashProbeOperator / ChHashJoinBridge / ChHashJoinNode——velox Operator/JoinBridge/PlanNode 要求，CH 无对应。
  • 20 个 tests/*.cpp：velox 侧新写单测，不对应 CH 测试。
  • 2 个 benchmark：ChHashJoinBenchmark.cpp（端到端）、ChHashTableLayerBenchmark.cpp（第 1 层公平三方对比）+ analyze_layer1_results.py。
对齐缺口 / CH 有本次未移植
  • hashed digest 生成未对齐：Port HashedKey.h 用 XXH3-128，CH hash128 用 SipHash128。哈希函子（UInt128TrivialHash 取低 64 位）已对齐，但 digest 算法未对齐。完整对齐需 SipHash + saved_hash 缓存成套改（见 HANDOFF_rebase_todo.md TODO 1b）。
  • two_level / TwoLevelHashMap：CH 大表分级哈希表，本次未移植。
  • ASOF / 多 join 类型分派：CH Inner/Left/Right/Full × All/Any/Semi/Anti/Asof 的 40+ 实例化，本次只做 inner-all 单路径。
  • low_cardinality / nullable KeyGetter 特化：CH HashMethodKeysFixed 的低基数/可空特化，本次未搬。
